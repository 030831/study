# 공부한 경험을 취업 준비로 연결하기

목표는 졸업 후 Java/Spring 백엔드 신입 지원이야. 현재는 3학년 2학기이며 정확한 졸업 연월, 희망 회사, 인턴 가능 시기는 확인하지 않았어. 그래서 이 문서는 합격 보장 로드맵이나 날짜별 할 일표가 아니야.

## 준비의 네 축

| 축 | 보여줄 결과 |
|---|---|
| 기본기 | Java·DB·HTTP·운영체제/네트워크 개념을 코드 동작과 연결한 설명 |
| 개발 | 요구사항을 구현하고 오류를 재현·수정한 코드와 검증 |
| 전달·협업 | 실행 가능한 안내, API 합의, 변경 리뷰, 피드백 반영 |
| 지원 | 본인 기여가 드러나는 이력서, 기술 설명, 목표 전형에 맞춘 코딩테스트 준비 |

기본 계층을 만드는 작업을 반복했다고 나머지가 자동으로 채워지지는 않아. 반대로 알고리즘 풀이 경험이 많아도 DB·HTTP·팀 개발 숙련도를 바로 증명하지는 못해. 각각 다른 증거로 확인해.

## 대표 경험 하나에 필요한 증거

대규모 서비스처럼 보이게 꾸미기보다 실제로 다룬 범위를 정직하게 적어.

1. **문제:** 어떤 입력/요청/사용 상황에서 무엇이 잘못되었나.
2. **판단:** 고려한 방법과 선택 이유, 받아들인 비용은 무엇인가.
3. **본인 작업:** 직접 설계·작성·리뷰한 부분과 참고한 자료/AI 도움은 어디인가.
4. **확인:** 같은 조건에서 이전/이후를 어떻게 비교했나. SQL, 테스트, 로그, 재현 절차 중 실제 근거를 붙인다.
5. **한계:** 아직 다루지 않은 상황과 다음 개선은 무엇인가.

성능을 주장한다면 데이터 건수, 실행 환경, 비교 조건, 반복 측정 여부를 함께 기록해. 측정하지 않은 대규모 트래픽이나 절감 수치를 만들어내지 않아. [사례 양식](templates/case-study.md)을 사용할 수 있어.

## library는 어디에 쓰일까

현재 도서 CRUD의 성공은 기본 흐름을 만들었다는 증거야. 그 자체를 차별화된 대표 프로젝트라고 단정하지 않아.

대출·개별 반납에서 관계와 상태를 직접 설계하고, 저장 실패를 검증하거나 요구 변경을 수행했다면 그것은 학습 과정의 구체적인 증거가 돼. 이후 이전 쇼핑몰의 복잡한 흐름을 스스로 개선할 수 있다면 같은 능력의 전이를 보여줄 수 있어.

library를 계속 키우는 것이 의무는 아니야. 독립적으로 다룰 수 있는 범위가 확인되면 학교 팀 프로젝트, 인턴, 실제 사용자가 있는 도구, 기존 프로젝트 개선 중 다음 경험을 선택해.

## 배포와 협업은 작게라도 실제로

- 다른 사람이 README를 보고 실행할 수 있는지 확인받는다.
- 환경 설정과 비밀 값을 코드에서 분리하고 실제 비밀은 자료/로그에 남기지 않는다.
- API 입력·응답·실패 사례를 공유하고 피드백을 받아 수정한다.
- Git에서 한 변경의 목적이 드러나는 커밋/PR을 만들고 리뷰에 답한다.
- 배포 후 오류를 발견했다면 원인·수정·검증·재발 방지를 기록한다. 오류를 일부러 공개 서비스에 만들지는 않는다.

실제 사람과 협업한 경험은 AI와 역할을 나눠 작업한 것과 구분해서 적어. AI를 썼다고 경험이 무효가 되는 것도 아니고, AI가 작성한 부분을 모두 내 설계라고 말하는 것도 아니야.

## 지원 준비는 언제 시작할까

프로젝트가 완벽해질 때까지 이력서 작성을 미루지 않아도 돼. 증거가 있는 경험부터 초안을 만들고, 기술 질문에 답해보면서 빈 부분을 확인해.

목표 회사가 정해지면 신입/인턴 공고 몇 개에서 아래만 추려 우선순위를 조정해.
- 필수와 우대의 구분, 회사가 사용하는 기술과 지원자가 반드시 알아야 하는 기술의 구분.
- 코딩테스트/과제/면접 절차와 졸업 예정자 지원 가능 시점.
- 실제 업무가 제품 개발, 내부 시스템, 데이터 처리, 운영 중 어디에 가까운지.

기술 목록을 전부 수강 계획으로 옮기지 않아. 예를 들어 공식 신입 공고의 한 사례에는 API 개발·SQL 운영·배포가 업무로, Git·문제 해결·의사소통이 우대로 제시돼 있어. 이 사례는 Node.js 계열이고 Java 신입 전체의 기준은 아니야. [링커리어 공식 신입 공고](https://linkareer.career.greetinghr.com/ko/o/135927) — 본문 확인 2026-09-06. 현재 모집 지속 여부는 지원 직전에 다시 확인해야 해.

## AI 발전에 대비하는 연습

미래 채용 규모나 도구 성능을 확정적으로 예측하지 않아. 현재 할 수 있는 준비는 도구의 출력에 대한 책임을 늘리는 거야.

- 새로운 핵심 개념은 먼저 직접 구현하거나 작은 실험으로 확인한다.
- 그다음 AI의 제안을 읽고 요구사항 위반·오류·과한 복잡성을 찾는다.
- 받아들인 변경은 테스트/SQL/실행 결과로 확인하고 설명한다.
- 도구 없이 막힌 지점과 도구가 있어도 검증하지 못한 지점을 따로 기록한다.

목표는 타이핑 속도로 AI와 경쟁하는 것이 아니라, 도구가 바뀌어도 요구를 이해하고 결과를 검증·수정할 수 있는 개발 능력을 쌓는 것이야.
